# AWS infrastructure

This directory defines the serverless deployment of 3D Photo Viewer with
**AWS CDK v2 (TypeScript)**. One stack, `PhotoViewer3D`, in Tokyo
(`ap-northeast-1`) holds everything. The account comes from your AWS profile,
and no account ID or credential is stored in the source.

## Architecture

```text
https://<distribution>.cloudfront.net            (one origin, no CORS)
 ├─ /          → S3 site bucket (static Next.js export + auth-config.json)
 ├─ /api/*     → API Gateway HTTP API ── Cognito JWT authorizer
 │                ├─ GET  /api/photos   → ListPhotos  → DynamoDB (newest-first GSI)
 │                ├─ POST /api/session  → Session     → CloudFront signed cookies
 │                └─ POST /api/uploads  → CreateUpload → presigned S3 POST
 └─ /media/*   → S3 media bucket (private, OAC), requires signed cookies

Browser ──presigned POST──▶ S3 upload bucket incoming/ ──event──▶ ProcessPhoto
   ProcessPhoto: EXIF date, SHA-256 dedup, 320/800/1600 WebP → media bucket + DynamoDB
```

- **Sign-in:** Cognito user pool, invitation only (self sign-up disabled).
  The frontend uses the Hosted UI with the authorization-code flow plus PKCE.
- **API:** every route requires a Cognito access token.
- **Images:** `<img>` tags can't send a bearer token, so `POST /api/session`
  sets three CloudFront signed cookies (`Path=/media/`, `HttpOnly`, `Secure`,
  `SameSite=Strict`, 12 hours). The frontend renews them hourly. The RSA
  signing key is generated by a custom resource. The private key exists only
  as the SSM SecureString `/photoviewer3d/cloudfront-signing-key/v1`. To rotate
  it, bump `KeyVersion` in `lib/photo-viewer-stack.ts`.
- **Uploads:** the presigned POST policy pins the key (`incoming/<uuid>/<name>`),
  the content type, the declared size (64 MiB maximum), the uploader and mtime.
  `ProcessPhoto` reproduces the local server's behavior:
  - It chooses the date from EXIF `DateTimeOriginal`/`CreateDate`, then the
    file mtime sent by the browser, then the S3 upload time.
  - EXIF dates without an offset are read in `Asia/Tokyo`. Override with
    `-c photoTimeZone=…`.
  - Variants use the same recipe: WebP q90, lanczos3, auto-orient, never enlarged.
  - The photo ID is the first 32 hex characters of the SHA-256 hash, so
    duplicates and retries are harmless.
  - Invalid files are deleted. Unexpected errors leave the upload in `incoming/`
    for Lambda's retries, and the upload bucket expires leftovers after 7 days.

### IAM

Every application Lambda has its own role, with permissions generated by CDK
`grant*` calls. No managed policies are attached and no resource is `*`.
The only hand-written statement lets the signing-key function put and delete
SSM parameters under `/photoviewer3d/cloudfront-signing-key/*`.

### Data safety

The media bucket (versioned; old versions expire after 30 days) and the
DynamoDB table (deletion protection, point-in-time recovery) are **retained**
if the stack is deleted. The site bucket, the upload bucket, the user pool and
the log groups (14-day retention) are removed with the stack. Invited users
would need to be recreated.

## Develop and validate

Requires Node.js 22 or newer. No AWS access is needed.

```bash
cd infra
npm install
npm test                     # stack assertions + Lambda unit tests (real sharp/exifr)
npx cdk synth --no-lookups
```

Sharp is installed into the ProcessPhoto bundle with its linux-x64 binaries,
not bundled by esbuild. Docker is not required on an x86-64 Linux host.

## Deploy

Credentials come from an external AWS CLI profile and are never stored in
this repository. The account was bootstrapped once with the CDK default
execution policy:

```bash
npx cdk bootstrap aws://<account>/ap-northeast-1 --profile <profile> \
  --cloudformation-execution-policies arn:aws:iam::aws:policy/AdministratorAccess
```

Infrastructure plus frontend, from the repository root:

```bash
npm run build:aws                              # static export using /api and /media
cd infra
npx cdk diff   PhotoViewer3D -c siteDir=../out --profile <profile>
npx cdk deploy PhotoViewer3D -c siteDir=../out --profile <profile>
```

`npm run deploy:aws` runs the build and the deploy together (set `AWS_PROFILE`).
Omitting `-c siteDir` deploys infrastructure only and leaves the current site
untouched. The deployment writes `auth-config.json` (region, pool, client and
Hosted UI domain; none of them secret) next to the static files and invalidates
CloudFront.

### Outputs

| Output | Purpose |
| --- | --- |
| `SiteUrl` | The application |
| `UserPoolId`, `UserPoolClientId`, `CognitoDomain` | Sign-in configuration |
| `UploadBucketName` | Target for migration uploads (`incoming/` prefix) |
| `MediaBucketName`, `PhotoTableName` | Stored photos and catalog |
| `DistributionId` | For manual CloudFront invalidations |

## Invite a user

```bash
aws cognito-idp admin-create-user --profile <profile> \
  --user-pool-id <UserPoolId> --username person@example.com \
  --user-attributes Name=email,Value=person@example.com Name=email_verified,Value=true \
  --desired-delivery-mediums EMAIL
```

Cognito emails a temporary password. The Hosted UI asks the user for a new
password (at least 12 characters, with upper case, lower case and digits) on
the first sign-in. Every invited user can upload.
